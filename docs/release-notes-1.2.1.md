# v1.2.1 · 修好播放器：频道能点、点开能播、播不了会说原因

这一版全在修播放器。起因是「点了频道里的节目不能播放」，查下去发现是三个问题叠在一起。

## 修复：播放器的「频道」标签是空的

进入播放器页后切到「频道」，列表永远显示「频道列表为空」，所以根本没东西可点。
原因是频道数据只在「电视源」页加载过，播放器从未拉取。现在切到该标签时才第一次拉取，并显示「正在加载频道…」。

## 修复：没有扩展名的 IPTV 地址播不了

频道库 373 个地址里有 **96 个没有扩展名**（`/live/fengshanggw`、`/douyu/605964` 这种），它们实际是 HLS 或 FLV。
旧逻辑只看 URL 后缀，判不出类型就当成普通文件塞给 `<video>`，浏览器必然黑屏，而且一声不响。

现在播放前先探一次源站：

- 看响应头 `content-type`，再读首块字节判断 `#EXTM3U` / `FLV` / `ftyp`
- 认出是 HLS 就交给 hls.js，FLV 交给 mpegts.js，MP4 直接播
- 实在认不出类型时，不硬塞给浏览器，改走 ffmpeg 本地桥接，至少能出画面
- 探测结果缓存 60 秒，不重复请求

反代也一起改了：不再依赖 `.m3u8` 后缀，凡是 `application/vnd.apple.mpegurl` 或首块以 `#EXTM3U` 开头的响应，一律按播放列表重写分片地址。实测某省台无后缀地址：播放列表 200，首个分片 5.1 MB 正常透传。

## 修复：播放失败没有任何提示

以前源站 404 时，`/api/play` 照样返回一个反代地址，`<video>` 加载失败但没人监听 `error`，界面就永远停在「正在连接…」。
现在：

- `<video>` 补 `error` / `stalled` 监听，按错误码给中文原因
- hls.js 的致命错误最多重试 2 次，之后报错不再无限静默重连
- 失败面板写清原因，并给出「重试」和「强制转码重试」两个按钮
- 源站 404 → 「源站返回 404，该频道链接已失效」；403 → 「拒绝访问（可能有防盗链或地区限制）」；返回网页 → 「这个地址返回的是网页，不是视频流」
- 失败会写进「运行日志」：`播放失败：<地址> —— <原因>`

## 升级提示

- 直接覆盖安装，配置无需迁移
- 公开 IPTV 源本身不稳定，碰到失效频道现在会明确告诉你原因，换一个频道即可
