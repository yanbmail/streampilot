## 修复：选源 / 选摄像头保存没反应、摄像头跑不起来

### 一、保存像「点了没反应」

**原因**：新建任务弹窗里根本没有「任务名称」输入框，也没有把校验失败的原因明确显示出来。点「保存并启动」时，如果推流目标还没填，代码会把错误塞进右下角一个小 toast——弹窗遮罩一盖、位置又远，看起来就是「什么都没发生」。

**修复**：

- 弹窗顶部新增**任务名称**输入框（默认「新建推流」，可随时改）
- 校验失败时，原因以红色提示条**直接显示在弹窗底部按钮上方**，同时**自动跳到出问题的标签页**、滚回顶部
- 保存按钮点下去变「保存中…」并禁用，不会再有「点了不知道有没有生效」
- 改了任意字段，旧的错误提示会自动消失
- 打开摄像头面板时自动选中第一台设备，避免「没选设备 → 被拦住」

### 二、摄像头选好了也跑不起来

**原因有两个，都在采集参数上**：

1. 原来 macOS 下固定传 `-f avfoundation -framerate 30 -video_size 1280x720`。设备不支持这个组合时 FFmpeg 只打印 `Configuration of video device failed, falling back to default.` 然后**卡住不吐帧**——界面显示「推流中」，实际 0 帧、没有文件，谁也看不出问题。
2. 摄像头打不开（最常见是 macOS 没给相机权限，或设备被会议/OBS 占用）时，FFmpeg 退出后还会按「断流自动重连」无限重试，日志刷屏，用户只看到一直转圈。

**修复**：

- macOS 采集只指定设备，**不再强制分辨率和帧率**，统一交给后面的 `scale` / `fps` 滤镜处理，任何摄像头都能出画面
- 摄像头 / 屏幕类任务：**一帧都没出就退出 → 直接标记异常、停止重试**，日志里写明排障步骤（系统设置 → 隐私与安全性 → 相机 / 屏幕录制，勾选运行程序后完全退出重开；确认设备没被占用）
- 加 20 秒兜底体检：摄像头/屏幕任务 20 秒还没出帧，自动停止并报「没有输出画面」及原因，不再假装在推流
- 摄像头面板加**「检测」按钮**：真正打开设备抓一帧，返回结论——
  - 权限被拒 → 「macOS 拒绝访问该设备：到系统设置…勾选运行 StreamPilot 的程序」
  - 被占用 → 「设备正被其他程序占用」
  - 模式不支持 → 「设备不支持当前分辨率/帧率组合」
  - 正常 → 「摄像头可用：已成功抓到一帧画面」
- 错误诊断表补充 `Input/output error`、`Configuration of video device failed`、`Selected pixel format not supported` 三条针对采集设备的判断

### 验证

- 界面新建任务（测试源 + 录制文件目标）：保存并启动成功，落盘 12 MB，状态推流中
- 不填目标直接点保存：弹窗底部出现红色提示「还没有填推流服务器地址：到「推流目标」填地址和推流码；只想先录制可以切换成「录制文件」」，并自动切到推流目标页
- 摄像头点「检测」：返回「摄像头打不开 —— macOS 拒绝访问该设备…」并给出授权路径（本机确实未授权相机）
- 摄像头任务启动失败：状态直接变「异常」，日志给出排查建议，不再无限重连

> 如果你要用摄像头：先到 **系统设置 → 隐私与安全性 → 相机**，把运行 StreamPilot 的程序（终端 / iTerm / WorkBuddy）勾上，然后**完全退出并重新打开它**，再点「检测」确认。
