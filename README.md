# StreamPilot · 跨平台推流控制台

仓库地址：**https://github.com/yanbmail/streampilot**

把「本地/屏幕/摄像头/网络流/电视源」统一变成可精确控参数的直播推流。
一套代码同时提供 **桌面应用**（Electron 窗口）和 **浏览器控制台**（局域网内手机、其他电脑可打开切流）。

- 引擎：Node.js + FFmpeg（子进程管理，实时解析指标）
- 界面：原生 Web（零构建），`hls.js` / `mpegts.js` 负责播放
- 平台：macOS（Apple Silicon / Intel）、Windows、Linux

---

## 1. 核心能力

### 推流输出（8 种目标）

| 协议 | 场景 | 关键参数 |
| --- | --- | --- |
| RTMP / RTMPS | B 站、抖音、YouTube、OBS 生态 | 服务器、应用名、推流码，默认 1935 |
| RTSP | 内网监控、流媒体服务器 | TCP 传输、0.1s muxdelay |
| SRT | 弱网、跨公网高质量回传 | 延迟、加密口令、pkt_size |
| UDP | 组播分发、内网广播 | TTL、pkt_size 1316 |
| HLS 本地 | 本地预览、切片分发 | 分片时长、列表长度 |
| HTTP-FLV 监听 | 浏览器低延迟播放 | 监听端口，播放器拉 `http://ip:port/live.flv` |
| 录制文件 | 直接落盘 mp4 / mkv / ts | 保存路径、容器 |
| 自定义完整 URL | 带鉴权参数的特殊平台 | 覆盖上面所有字段 |

### 推流源（6 种）

- **测试源**：彩条 / 计数 / 渐变等 FFmpeg 内置图样，用于验证链路
- **媒体文件**：单个文件，可循环
- **多文件轮播**：`concat` 无缝拼接，播完自动续下一个
- **屏幕区域**：整屏或指定 `x/y/宽/高` 裁剪，可带光标
- **摄像头**：AVFoundation / DirectShow / V4L2，可带麦克风
- **网络流**：RTSP / RTMP / HLS / HTTP-FLV / UDP / SRT 的任意源

### 多平台分发（一份编码推多路）

- 一个任务除主目标外，最多再加 **8 个分发目标**（RTMP / RTMPS / RTSP / SRT / UDP）
- 底层用 FFmpeg `tee` 复用同一份编码，**CPU 占用与单路接近**，不是重复转码
- 每路带 `onfail=ignore`：某一路挂掉只记日志，其余照常推
- 典型用法：B 站 + 抖音 + YouTube 同时开播，只配一次画面参数

### 同步录制（边推边存）

- 推流同时把**同一份码流**写一份到本地，不额外编码
- 容器可选 MP4（通用）/ MKV（中断可恢复）/ TS（最抗异常）
- 路径留空自动落到 `~/.streampilot/records`，断流重连后继续写同一文件
- 与多平台分发可叠加：一边推 3 个平台、一边本地存档

### 多码率阶梯转码（一次解码，多档同时出）

- 一个任务最多 **4 档**，每档独立分辨率 / 码率 / 帧率 / preset / 协议 / 目标
- 底层用 `-filter_complex split=N`，**只解码一次**，再分别编码；比开多个任务省一大截 CPU
- 一键生成 1080P / 720P / 480P 三档（码率按 6000 / 3000 / 1200 kbps 起，可再改）
- 典型用法：1080P 推 B 站、720P 推抖音、480P 推海外平台或留给弱网观众
- 阶梯模式下 HLS 档会落到 `hls/<任务ID>_r1`、`_r2`…，播放地址在表单里直接给出
- 任意一档支持 RTMP / RTMPS / RTSP / SRT / UDP / HTTP-FLV / HLS / 录制文件

### 排播表（一周定时播）

- 周视图网格：7 天 × 24 小时，点空白格直接在该时刻新建，点色块编辑
- 每条排播指定：名称、要推的任务、星期几（可多选，含工作日/周末快捷）、开始时刻、结束方式（**指定时刻** 或 **按时长**，1–1440 分钟）
- 跨午夜自动识别：`23:30 → 01:00` 会标注「跨午夜」，第二天凌晨照样正常停
- 到点自动开播、到点自动停播；同一任务被多条排播共用时不会误停（要等最后一条结束）
- 也可以临时「立即开播 N 分钟」试跑，到时间自动断流，不影响既定的排播
- 排播引擎每 10 秒对一次表，起播失败会退避 60 秒重试并在界面标红原因
- 关掉排播总开关即整体暂停，单条也能单独禁用

### 推流模板（一套参数反复用）

- 把「画面 + 音频 + 目标 + 录制 + 阶梯」存成模板，**输入源不写进模板**，套用时不会被覆盖
- 三种来源：从现有任务一键存、手动建空白模板、列表里复制一份改名
- 套用方式：任务编辑器里单选套用，或模板页多选任务**批量套用**
- 也能「用模板新建任务」，从零起一个已配好码率与目标的任务
- 模板卡片直接显示画面规格、音频、主目标或阶梯档数，方便辨认

### 内置 RTMP 收流服务端

- 不装 nginx-rtmp / SRS，本机直接成为接收端：OBS、手机推流 App 推 `rtmp://本机IP:1935/live/流名`
- 收到的流实时出现在「设置 → 内置 RTMP 收流服务」，可**预览**、**复制播放地址**、**一键转推**
- 同时提供 HTTP-FLV 播放端点（端口默认 8399），浏览器和本应用都能直接播
- 启动状态记在配置里，重启应用自动恢复

### 画质与码流（实时可控）

- 分辨率：720P / 1080P / 2K / 4K / 竖屏，或任意自定义宽高
- 缩放策略：留黑边（fit）/ 裁切填满（cover）/ 拉伸（stretch）
- 码率控制：**CBR**（直播平台要求）/ VBR / CRF
- 编码器：x264 / x265（软件）、VideoToolbox（macOS 硬件），按机器自动探测
- 音频：AAC / Opus / MP3 / AC3，码率、采样率、声道可调
- GOP、preset、profile、B 帧策略可调；也可「视频直通」不重编码

### 电视源（IPTV）

- 预置公开源：IPTV-org（中国/全球/新闻/体育/港澳台）、范明明 live、YanG-1989 聚合、TVlive
- 支持 **M3U / M3U8 / TXT(#genre,#EXTINF)** 与 JSON 列表，可本地导入或粘贴
- 自动去重、按分组/画质筛选、关键词搜索、分页
- 频道健康检查（HTTP 探测 + 延迟），标记可用/失效
- **一键转推**：任意频道 → 自定义码率/分辨率 → 推到任意目标协议
- 部分源跨域或有防盗链，内置本地代理与请求头透传

### 播放器

- 支持 HLS / HTTP-FLV / RTSP / RTMP / UDP / SRT / 本地文件
- 浏览器不支持的协议自动走 FFmpeg 本地转封装
- 频道收藏、播放历史、粘贴地址直播

### 备份与可靠性

- 配置写入采用 **原子写 + `.bak` 双份**
- 定时快照（默认 30 分钟、保留 40 份），停止推流时自动快照一次
- 一键恢复任意快照、导出/导入完整配置 JSON
- 断流自动重连（可配次数与退避）
- 进程意外退出后仍保留日志与错误诊断，便于定位

## 2. 快速开始

### 依赖

- **Node.js ≥ 18**
- **FFmpeg ≥ 5**（需要 `ffmpeg`、`ffprobe` 在 PATH 中，或稍后在设置里指定绝对路径）

```bash
# macOS
brew install ffmpeg
# Ubuntu / Debian
sudo apt install ffmpeg
# Windows: 下载 https://www.gyan.dev/ffmpeg/builds/ 解压后把 bin 加入 PATH
```

### 安装与运行

```bash
git clone https://github.com/yanbmail/streampilot.git
cd streampilot
npm install

# 桌面应用（推荐）
npm start

# 或者只跑后台服务，用浏览器访问 http://127.0.0.1:8377
npm run serve
```

首次启动会自动创建数据目录 `~/.streampilot`（配置、快照、HLS 片段都在这里）。

### 更新代码与同步版本

```bash
./scripts/sync.sh "这次改了什么"   # 提交并推送到 GitHub
./scripts/publish.sh              # 只推送，不改动提交
```

详见 `docs/PUBLISH.md`。

### 桌面端与浏览器端

- 桌面窗口和 `npm run serve` **共用同一数据目录**，配置互通
- 设置 → 网络与远程访问 → 打开「允许局域网访问」，即可在手机/平板/另一台电脑用 `http://<本机IP>:8377` 管理
- 开启局域网访问后建议设置访问令牌（`lanToken`），避免同网段任意访问

### macOS 权限

屏幕与摄像头采集需要在「系统设置 → 隐私与安全性」里给对应程序授权：

- 屏幕录制（屏幕区域推流必须）
- 摄像头、麦克风（摄像头推流必须）

未授权时 FFmpeg 会报 `Operation not permitted`，任务卡片上会给出中文诊断提示。

## 3. 典型用法

### 3.1 推流到 B 站 / 抖音

1. 推流任务 → 新建推流
2. 输入源选「屏幕区域」或「媒体文件」
3. 画面：1080P、30fps、CBR 6000 kbps、编码器按机器选硬件或 x264
4. 推流目标：RTMP，填平台给的「服务器地址」和「推流码」
5. 保存并启动，总览页能看到实时码率曲线

> 平台地址通常形如 `rtmp://live-push.bilivideo.com/live-bvc/`，推流码是一长串参数。若平台要求整串 URL，直接粘到「完整地址覆盖」。

### 3.2 把电视源转成自己的推流

1. 电视源 → 更新全部源（或导入自己的 m3u）
2. 找到频道 → 点「转推」
3. 在弹出表单里设分辨率/码率/目标协议
4. 启动后该频道就被重新编码成你要求的码流

适合把低码率公开源统一成 1080P/6Mbps，或把 HLS 源转成 RTMP 喂给平台。

### 3.3 屏幕区域推流

1. 输入源 →「屏幕区域」
2. 选显示器，点「全屏」或手动填 `x / y / 宽 / 高`
3. 需要鼠标指针就打开「采集光标」
4. 之后与普通推流一致

### 3.4 局域网低延迟分发（HTTP-FLV）

推流目标选「HTTP-FLV」，设监听端口（默认 8380），启动后：

- 播放器地址：`http://<本机IP>:8380/live.flv`
- 任何支持 FLV 的播放器（PotPlayer、VLC、OBS、本应用播放器）都能拉

### 3.5 一份画面同时开播多个平台

1. 推流任务 → **推流目标**：主目标填第一个平台（例如 B 站）
2. 下方「多平台分发」→ **添加目标**，逐个填抖音、YouTube 的地址与推流码
3. 「同步录制」可选打开，顺手存一份原始文件
4. 保存并启动 —— 只编码一次，三路同时出流

某一路地址写错或平台断线，只会丢那一路，其余不受影响（日志里会有 `Slave ... failed ... continuing`）。

### 3.6 用 OBS / 手机推流进来，再转推出去

1. 设置 → **内置 RTMP 收流服务** → 启动收流
2. OBS「服务器」填 `rtmp://本机IP:1935/live`，「串流密钥」自定义，例如 `myphone`
3. 推上来后，设置页会出现这一路流，可点「预览」确认画面
4. 点「转推」——自动按 720P / 3 Mbps 建一个任务，再把它改成要推的平台即可
5. 也可以只录制：转推任务里把目标改成「录制文件」，或直接开「同步录制」

### 3.7 一次解码，1080P/720P/480P 分别推三个平台

1. 推流任务 → 新建推流，输入源照常选
2. **推流目标** 页签顶部打开「多码率阶梯转码」
3. 点「生成 1080/720/480」，自动出三档（分辨率、码率、preset 都填好了）
4. 逐档把目标改掉：第 1 档 B 站、第 2 档抖音、第 3 档另一个平台
5. 保存启动 —— 日志会打印「一次解码输出 3 档」，总览页能看到整条链路的总码率

> 想加第四档就点「添加一档」，最多 4 档；每档的分辨率 chip 可以一键切 1080P / 720P / 480P / 竖屏。
> 某档填错只影响那一档，其余继续推。

### 3.8 一周节目单自动排播

1. 左侧「排播表」→ 在周视图里点某个空白格（比如周三 20:00）
2. 填名称、选要推的任务、勾星期（可多选）、设开始时间和结束方式
3. 保存后色块出现在网格上，同时下面有列表视图，能看「下次开播」时间
4. 到点自动开播，到点自动停播；日志里会写「排播「晚间档」开始执行 / 时段结束，已停止推流」

**结束方式的两种含义**

- 指定时刻：如 `20:00 → 22:00`，到 22:00 停
- 按时长：如 `20:00` 起播、时长 90 分钟，到 21:30 停（适合时长不固定的节目）

**临时试跑**：列表里点「立即开播」，填分钟数，到点自动断；期间不影响既定排播，点「立即停止」可提前结束。

### 3.9 把一套参数存成模板，批量复用

1. 在任务列表里对某个配好的任务点「存为模板」，或者在任务编辑器顶部点「存为模板」
2. 之后新建任务时，编辑器顶部会显示「N 套可用」→ 点「套用模板」单选一个，画面/音频/目标/录制/阶梯全部就位
3. 要一次改多个任务：左侧「推流模板」→ 卡片上点「快速套用」→ 勾任务 → 应用
4. 想从模板起新任务：卡片上点「用模板新建」

> 模板**不含输入源**，所以给 A 任务（屏幕）和 B 任务（网络流）套同一个模板不会把源改掉。
> 模板会连推流码一起保存，导出的配置 JSON 里有平台推流码，分享前请自行删掉。

## 4. 目录结构

```
streampilot/
├── electron/main.js      桌面壳：窗口、原生文件对话框、单实例
├── server/
│   ├── index.js          HTTP 服务与全部 API
│   ├── ffmpeg.js         FFmpeg 参数构建、设备/编码器探测、指标解析
│   ├── jobs.js           推流任务生命周期、日志、重连、体积采样
│   ├── scheduler.js      排播引擎：时间窗口计算、自动起停、未来节目单
│   ├── iptv.js           电视源抓取、解析、去重、健康检查
│   ├── preview.js        播放转封装（RTSP/FLV → 浏览器可播）
│   ├── rtmp-server.js    内置 RTMP 收流服务（node-media-server 封装）
│   ├── config.js         配置存储：原子写、快照、导入导出、任务/排播/模板规范化
│   └── util.js
├── web/                  前端（无需构建）
│   ├── index.html
│   ├── css/app.css
│   ├── js/{app,views,job-form,schedule,templates,tv,api,util}.js
│   └── vendor/           hls.js、mpegts.js
├── scripts/
│   ├── launch.js         启动器（清理 ELECTRON_RUN_AS_NODE 等环境干扰）
│   ├── publish.sh        推送仓库（默认推到 GitHub）
│   └── sync.sh           一键提交 + 推送
└── docs/                 发布与维护说明
```

数据目录 `~/.streampilot`：

```
config.json        主配置（任务、设置、播放器数据）
config.json.bak    上一次的配置，损坏时自动回退
backups/           定时快照
channels.json      电视源频道库
hls/<任务ID>/      HLS 输出切片
preview/           播放转封装临时文件
tmp/               多文件轮播的 concat 清单
```

## 5. 常见问题

**任务起不来，日志显示 `No such file or directory: ffmpeg`**
FFmpeg 不在 PATH。设置 → FFmpeg 路径填绝对路径，例如 `/opt/homebrew/bin/ffmpeg`。

**`Operation not permitted`**
macOS 权限未授予，见上文「macOS 权限」。

**`Connection refused` / `404` / `401`**
推流地址、应用名、推流码有一项不对，或平台尚未开播。日志里会给出中文诊断。

**电视源刷新失败 / 频道打不开**
公开 IPTV 源本身不稳定，且部分源限制了地区或需要特定 UA。可以：换一个源、在播放器「高级」里改 UA/Referer、或用自己的 m3u 替换。

**HLS 播放延迟大**
把分片时长调到 1–2 秒、列表长度 3–6；要更低延迟请改用 HTTP-FLV。

**需要重新打包分发**
```bash
npm run dist:mac     # dmg + zip
npm run dist:win     # nsis + portable
npm run dist:linux   # AppImage + deb
```

## 6. 备份与迁移

- 设置 → 配置备份：立即备份 / 导出 / 导入
- 恢复：快照列表点「恢复」，当前配置会先自动备份一份再覆盖
- 迁移到新机器：导出 JSON → 新机器导入即可

## 7. 开发约定

- 前端零构建：改完 `web/` 直接刷新浏览器（硬刷新可绕过缓存）
- 后端改动需要重启 `npm run serve`
- 所有 FFmpeg 参数集中在 `server/ffmpeg.js`，新增协议只需在 `buildTargetUrl` / `buildOutput` 加一个分支
- 新增源类型：`buildInput` 加分支 + `job-form.js` 的 `SOURCE_TYPES` 加一项

- 修复**播放 1~2 秒就自动停止**：点频道播放会写入播放历史 → 触发配置变更广播 → 前端 900 毫秒后整页重渲染 → `<video>` 元素被替换成新的空元素，刚起播的流必然被掐断。现在播放器页在「正在播放」或「正在输入地址」时不再整页重渲染，只刷新左侧列表与「收藏 N」计数
- 顺带：收藏/取消收藏、播放历史变化不再打断正在播的画面

### v1.2.1

- 修复**播放器「频道」标签为空**：切到该标签时才第一次拉频道列表，之前没拉过就一直是「频道列表为空」
- 修复**无扩展名的 IPTV 地址播不了**：`/live/xx`、`/douyu/123456` 这类地址是 HLS，但过去只按 URL 后缀判断，被当成普通文件塞给 `<video>`，必然黑屏。现在先探测响应头与首块字节，认出 HLS / FLV / MP4 再用对应播放器
- 修复**播放失败没有任何提示**：给 `<video>` 补 error/stalled 监听，HLS 只重试两次就报错；失败面板给出原因与「重试 / 强制转码重试」
- 反代改进：`application/vnd.apple.mpegurl` 或首块为 `#EXTM3U` 的响应一律按播放列表改写分片地址（不再依赖 `.m3u8` 后缀）；源站 404/403 直接返回可读中文原因；返回网页内容时报「不是视频流」，不再静默空转
- 播放失败会写进「运行日志」（`播放失败：<地址> —— <原因>`），方便排查
- 「强制转码重试」失败不再静默，会把原因显示出来
